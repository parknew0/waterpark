# Waterpark 데이터 수집 계획

> 확인일: 2026-08-22
>
> 상태: 공식 제공 페이지와 필드를 확인했고, 경북 GIS건물통합정보 전체데이터와 건축HUB 건축물대장 후보 자료를 실제 확보했다. 다른 원본은 항목별 상태를 따른다.
>
> 원칙: 실제 행 수, 결측률과 기간 범위는 경상북도 원본 또는 명시한 후보 범위를 확보한 뒤 기록한다.

## 1. 목표 데이터

기본 목표는 **건물 단위 침수 위험 예측용 표형 데이터셋**이다.

초기 집계 단위는 다음과 같다.

```text
한 행 = 특정 건물 + 특정 호우 사건
```

다만 1시간 내 위험을 학습하려면 기준 시각이 추가되어야 한다.

```text
한 행 = 특정 건물 + 특정 호우 사건 + 예측 기준 시각(as_of_time)
```

두 형태의 차이와 XGBoost에 주는 영향은 [전처리 및 XGBoost 적용 가능성](./02-preprocessing-and-xgboost-feasibility.md)에 정리한다.

## 2. 총 데이터 소스: 최소 6개 원본 묶음

## 3. 따로 있는 데이터를 한 건물에 붙이는 방법

사용자의 이해가 맞다. 원본에는 “A 건물의 고도는 8m이고 하천까지 200m”라는 완성된 행이 없다. **건물 Polygon을 중심으로 다른 공간·시간 데이터를 직접 붙여 하나의 분석용 테이블을 만들어야 한다.**

연결 방식은 세 가지다.

| 연결 방식 | 연결할 데이터 | 쉬운 설명 |
| --- | --- | --- |
| ID·주소 연결 | 건물 도형 `D4` + 건축물대장 `D3` | 실제 검증 결과 건물 단위 1:1 키는 없고 `PNU`(필지)로만 연결된다. 필지 단위로 지하층·용도를 붙인 뒤 그 필지의 건물들에 적용한다 |
| 위치 연결 | 건물 `D4` + DEM `D5` + 하천 `D6` + 침수흔적 `D1` | 건물이 어느 높이에 있는지, 하천과 얼마나 떨어졌는지, 침수 영역과 겹치는지 계산 |
| 시간 연결 | 침수 사건 `D1` + 강수 `D2` | 침수 시작시각을 기준으로 그 전 1·6·24시간의 비를 계산 |

### 3.1 먼저 건물 기본 테이블을 만든다

기준은 `D4 GIS건물통합정보`의 건물 Polygon이다. 여기에 `D3 건축물대장` 속성을 연결한다.

| building_id | building_geometry | address | main_purpose | underground_floor_count | parking_capacity |
| --- | --- | --- | --- | ---: | ---: |
| A001 | Polygon | 포항시 … | 공동주택 | 2 | TBD |

정확한 공통 키는 실제 파일의 정의서를 받은 뒤 확정한다. 공통 ID가 없다면 법정동 코드·본번·부번·주소 등을 조합해 연결하고, 일부 표본을 직접 확인한 뒤 매칭률을 기록한다.

### 3.2 건물별 정적 공간 특징을 붙인다

건물 기본 테이블의 위치를 이용해 DEM과 하천 데이터를 계산한다.

| building_id | elevation_m | relative_elevation_m | river_distance_m |
| --- | ---: | ---: | ---: |
| A001 | 8 | -3 | 200 |

- DEM에는 건물 ID가 없으므로 건물 중심점 또는 면적과 겹치는 격자의 높이를 읽는다.
- 하천 데이터에도 건물 ID가 없으므로 건물에서 가장 가까운 하천 선까지 거리를 계산한다.
- 이 결과를 `building_id`로 건물 기본 테이블에 붙인다.

그러면 다음과 같은 **건물 정적 특징 테이블**이 생긴다.

| building_id | main_purpose | underground_floor_count | elevation_m | relative_elevation_m | river_distance_m |
| --- | --- | ---: | ---: | ---: | ---: |
| A001 | 공동주택 | 2 | 8 | -3 | 200 |

### 3.3 건물과 침수 사건을 연결한다

침수흔적도에서 날짜·시각·재해명을 정리해 `event_id`를 만든다. 이후 건물 Polygon과 침수 Polygon을 겹친다.

| building_id | event_id | event_start | overlap_ratio | flood |
| --- | --- | --- | ---: | ---: |
| A001 | EVENT-001 | 2022-09-06 04:00 | 0.82 | 1 |

침수 Polygon과 겹치지 않았다는 이유만으로 모든 건물을 바로 `flood=0`으로 두지 않는다. 같은 호우 사건의 영향권 또는 확인 가능한 조사 범위 안에서 음성 후보를 정해야 한다.

### 3.4 사건 시각에 강수 특징을 붙인다

기상청 시간자료에서 사건 시작 전의 강수량을 합산한다.

| event_id | station_id | rain_1h | rain_6h | rain_24h |
| --- | --- | ---: | ---: | ---: |
| EVENT-001 | 138 | 40 | 120 | 280 |

ASOS 한 지점만 사용하면 이 표를 `event_id`로 붙일 수 있다. 여러 AWS 지점을 사용하면 건물마다 가까운 관측소를 찾거나 보간해야 하므로 `building_id + event_id` 기준의 강수 특징 테이블이 된다. 어느 방식을 사용할지는 실제 지점 분포와 결측을 본 뒤 결정한다.

### 3.5 마지막에 학습용 테이블로 합친다

```text
건물 정적 특징
+ 건물×침수 사건 라벨
+ 사건 또는 건물×사건 강수 특징
= 최종 학습용 테이블
```

| building_id | event_id | rain_1h | rain_6h | rain_24h | elevation_m | relative_elevation_m | underground_floor_count | river_distance_m | flood |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A001 | EVENT-001 | 40 | 120 | 280 | 8 | -3 | 2 | 200 | 1 |
| A002 | EVENT-001 | 40 | 120 | 280 | 20 | 5 | 1 | 1,300 | 0 |

이 최종 행은 원본 어디에도 존재하지 않는다. 6개 원본을 ID·위치·시간 기준으로 연결해 새로 만드는 Waterpark의 분석용 파생 데이터다.

### 접근 방식 분석

- 공식 API 문서에 공개된 요청 변수는 `serviceKey`, `numOfRows`, `pageNo`, `returnType`뿐이다.
- 지역·연도 필터 파라미터가 보이지 않으므로 전체 페이지를 받은 뒤 `STDG_CTPV_CD`, `STDG_SGG_CD`, 날짜로 로컬 필터링해야 할 가능성이 높다.
- 기존 자료의 공개 응답에는 CRS 필드가 없다. 새 위선의 X·Y 좌표계는 플랫폼 공식 문의 답변에서 `EPSG:3857`로 확인됐지만, 기존 `GEOM`도 같다고 자동 가정하지 않고 기준점 대조를 거친다.
- 플랫폼은 공공기관 데이터의 이용허락을 공공누리 제3유형으로 안내한다. 학습용 변환과 가공 결과 재배포가 가능한 범위는 별도 확인이 필요하다.

2025년에 별도 등록된 심선·위선 자료는 구조가 다르다. 위선은 시작·종료일자와 시분, 평균침수위, X·Y를 제공하지만 `GEOM` Polygon은 제공하지 않는다. 따라서 건물 내부 침수 여부를 직접 판정하려면 기존 Polygon 자료의 경북 기간·커버리지를 먼저 확인해야 한다.

### 수집 판단

API를 통해 원본을 받는 것 자체는 가능하다. 다만 XGBoost 라벨로 사용할 수 있는지는 다음 세 가지를 전체 데이터에서 확인해야 한다.

- 포항의 독립적인 침수 사건 수
- 시작일·시각의 결측 및 정밀도
- 침수 Polygon이 실제 조사 범위를 얼마나 완전하게 대표하는지

## 5. 기상청 강수 — Feature 후보

### 공식 제공 정보

| 항목 | 확인 내용 |
| --- | --- |
| 데이터명 | 종관기상관측 ASOS 시간자료, 방재기상관측 AWS 자료 |
| 제공처 | [기상자료개방포털 ASOS](https://data.kma.go.kr/data/grnd/selectAsosList.do?pgmNo=34), [AWS](https://data.kma.go.kr/data/grnd/selectAwsList.do?pgmNo=35) |
| API 명세 | [기상청 API허브 지상관측](https://apihub.kma.go.kr/apiList.do) |
| 형식 | 포털 파일셋은 연 단위 ZIP/CSV, 조회 화면은 CSV/Excel, API는 텍스트/CSV형 응답 |
| 인증 | API허브 활용 신청과 인증키 필요 |
| 포항 지점 | ASOS 표준지점번호 `138`, 지점명 `포항` 확인 |
| 행 수 | `TBD` — 선택 지점·기간·결측을 반영해 확보 후 산정 |

### 확인된 ASOS 시간자료 필드

사용자가 제안한 `STN_ID`, `DATE`, `TIME`, `SUM_RN`은 정규화 후 사용할 수 있는 이름이며 공식 API의 원본 필드는 다르다.

| 원본 필드 | 공식 의미 | 정규화 후보 |
| --- | --- | --- |
| `STN` | 국내 지점번호 | `station_id` |
| `TM` | 관측시각, KST | `observed_at` |
| `RN` | 강수량(mm) | `rainfall_mm` |
| `RN_DAY` | 해당 관측시간까지의 일강수량(mm) | 검증용 일 누적값 |
| `RN_INT` | 강수강도(mm/h) | `rain_intensity_mm_h` |
| `IR` | 강수 포함·무강수·결측 관련 코드 | 품질 및 결측 판별 |

API허브의 ASOS 기간 조회는 한 번에 최대 31일이다. 장기간 학습자료는 연 단위 CSV 파일셋을 받는 편이 호출 횟수와 재현성 면에서 더 적합하다. AWS는 더 촘촘한 지점망을 제공하지만 지점별 보유기간과 품질을 별도로 확인해야 한다.

### 행 수 해석

한 관측소의 완전한 10년 시간자료는 이론적으로 `365 × 24 × 10 ≈ 87,600`행이다. 윤년, 결측, 관측소 이력에 따라 실제 값은 달라진다. 이 수는 강수 원본 행 수일 뿐이며 최종 학습 표의 독립 표본 수는 아니다.

### 수집 판단

강수 원본 수집과 `rain_1h`, `rain_6h`, `rain_24h`, `max_rain` 생성은 가능하다. 다만 포항 ASOS 한 지점만 사용하면 같은 사건·시각의 모든 건물이 동일한 강수 특징을 갖는다. 건물별 국지 강우 차이를 만들려면 AWS 등 여러 지점의 좌표와 건물 위치를 결합해야 한다.

## 6. 건축물 데이터 — 건물 Feature 및 공간 단위

건축물 속성과 공간 도형은 분리해서 확인해야 한다.

### A. 건축물대장 표제부

| 항목 | 확인 내용 |
| --- | --- |
| 제공처 | [공공데이터포털 건축물대장 표제부](https://www.data.go.kr/data/15044720/fileData.do), [건축HUB 건축물대장정보 OpenAPI](https://www.data.go.kr/data/15134735/openapi.do) |
| 형식 | 전체 파일 XLSX, 활용 신청형 REST API |
| 주요 확인 속성 | 관리건축물대장PK, 주소·법정동 코드, 건물명, 주용도, 지상층수, 지하층수, 층별 용도, 옥내·옥외 주차 관련 수·면적 |
| 좌표/도형 | 표제부 설명에는 위도·경도 또는 건물 Polygon이 없음 |
| 행 수 | `TBD` — 포항 필터 및 중복 정리 후 산정 |

사용자가 제안한 `LAT`, `LON`은 건축물대장 표제부에서 직접 확인되지 않는다. 주소/법정동/지번을 공간 건물 데이터와 연결해야 한다.

또한 `지하층수 > 0`은 지하 공간의 존재를 뜻할 뿐, 지하주차장을 직접 보장하지 않는다. `옥내 주차`도 지상 주차동일 수 있다. [건축HUB 층별개요](https://www.hub.go.kr/portal/opn/tyb/idx-bdrg-flr.do)의 `층구분코드=10(지하)` 행에서 주차장 용도를 확인하는 방법을 함께 사용하고, 근거 부족은 `false`가 아니라 `unknown`으로 남긴다.

### B. GIS건물통합정보

| 항목 | 확인 내용 |
| --- | --- |
| 제공처 | [VWorld GIS건물통합정보](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=NA&dsId=18) |
| 형식 | 건물 Polygon을 포함한 SHP |
| 좌표계 | 최근 배포본 `EPSG:5186`, 과거 배포본 `EPSG:5174`로 페이지에 표기 |
| 갱신 | 월간·일간 변동 데이터 |
| 접근 | VWorld 로그인 필요, 대용량 다운로드 솔루션 안내 |
| 경북 전체 목록 | `경상북도 + 전체데이터(AL) + SHP`로 조회 가능. 2026-08-22 확인한 최신 기준일 2026-08-09, 약 290MB |
| 행 수 | `TBD` — 경북 전체 파일 확보 후 산정 |

VWorld 페이지는 SHP 속성이 `A0 ... An`으로 표시되며 별도 컬럼 정의서를 참고하라고 안내한다. 정의서에서 GIS건물통합식별번호, PNU, 법정동·지번, 용도, 건물명·동명, 지상·지하층 수를 확인했다. 사용자가 확인한 `CH_D010`은 일간 변동분이므로 최초 경북 전체 목록에는 사용할 수 없고 `AL_D010` 전체데이터가 필요하다. 정확한 건물 ID와 건축물대장 연결 키는 실제 경북 파일을 받은 뒤 매칭률로 확정한다.

### 수집 판단

건물 Polygon과 지하층·용도 속성을 각각 확보할 경로는 존재한다. 그러나 두 자료의 연결 키와 매칭률을 확인하기 전에는 `BULD_ID`, 좌표, 지하층 수가 한 행에 바로 온다고 가정할 수 없다.

## 9. 전체 수집 판단

현재 공식 제공 경로만 놓고 보면 다음 조합은 기술적으로 구성 가능하다.

```text
침수흔적 Polygon
+ 기상청 시간 강수
+ 건물 Polygon 및 건축물대장 속성
+ DEM 래스터
+ 하천 중심선
```

그러나 아직 “학습 가능한 데이터셋이 확보됐다”고 말할 수는 없다. 전체 데이터 확보 후 다음 수치가 나와야 한다.

- 포항의 실제 건물 수와 지하주차장 후보 수
- 침수 Polygon과 겹치는 양성 건물 수
- 서로 다른 침수 사건 수
- 정확한 시작 시각이 있는 사건 비율
- 데이터셋 간 건물 매칭률
- 컬럼별 결측률과 공간·시간 커버리지

건물 위치·지하주차장·시간 강수·침수 기록만 따로 확인한 결과와 직접 확인 순서는 [건물·강수·침수 데이터 소스 확인서](./04-building-rain-flood-source-verification.md)에 정리했다.
