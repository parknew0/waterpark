# Waterpark 데이터 수집 계획

> 확인일: 2026-08-22
>
> 상태: 공식 제공 페이지와 공개 샘플을 확인한 단계. 전체 원본 데이터는 아직 확보하지 않았다.
>
> 원칙: 포항 필터 적용 후 실제 행 수, 결측률과 기간 범위는 전체 데이터 확보 후 기록한다.

## 1. 목표 데이터

기본 목표는 **건물 단위 침수 위험 예측용 표형 데이터셋**이다.

초기 집계 단위는 다음과 같다.

```text
한 행 = 특정 건물 + 특정 호우 사건
```

다만 1시간 내 위험을 학습하려면 기준 시각이 추가되어야 한다.

```text
한 행 = 특정 건물 + 특정 호우 사건 + 예측 기준 시각(as_of_time)
```

두 형태의 차이와 XGBoost에 주는 영향은 [전처리 및 XGBoost 적용 가능성](./02-preprocessing-and-xgboost-feasibility.md)에 정리한다.

### 접근 방식 분석

- 공식 API 문서에 공개된 요청 변수는 `serviceKey`, `numOfRows`, `pageNo`, `returnType`뿐이다.
- 지역·연도 필터 파라미터가 보이지 않으므로 전체 페이지를 받은 뒤 `STDG_CTPV_CD`, `STDG_SGG_CD`, 날짜로 로컬 필터링해야 할 가능성이 높다.
- 공개 샘플의 좌표값은 투영좌표이지만 응답에 CRS 필드가 없다. 값의 범위는 Web Mercator와 유사해 보이지만 이는 추정이며, 공간 교차 전에 제공기관 확인 또는 기준점 대조가 필요하다.
- 플랫폼은 공공기관 데이터의 이용허락을 공공누리 제3유형으로 안내한다. 학습용 변환과 가공 결과 재배포가 가능한 범위는 별도 확인이 필요하다.

### 수집 판단

API를 통해 원본을 받는 것 자체는 가능하다. 다만 XGBoost 라벨로 사용할 수 있는지는 다음 세 가지를 전체 데이터에서 확인해야 한다.

- 포항의 독립적인 침수 사건 수
- 시작일·시각의 결측 및 정밀도
- 침수 Polygon이 실제 조사 범위를 얼마나 완전하게 대표하는지

### 공식 제공 정보

| 항목 | 확인 내용 |
| --- | --- |
| 데이터명 | 종관기상관측 ASOS 시간자료, 방재기상관측 AWS 자료 |
| 제공처 | [기상자료개방포털 ASOS](https://data.kma.go.kr/data/grnd/selectAsosList.do?pgmNo=34), [AWS](https://data.kma.go.kr/data/grnd/selectAwsList.do?pgmNo=35) |

| 형식 | 포털 파일셋은 연 단위 ZIP/CSV, 조회 화면은 CSV/Excel, API는 텍스트/CSV형 응답 |
| 인증 | API허브 활용 신청과 인증키 필요 |
| 포항 지점 | ASOS 표준지점번호 `138`, 지점명 `포항` 확인 |
| 행 수 | `TBD` — 선택 지점·기간·결측을 반영해 확보 후 산정 |

### 확인된 ASOS 시간자료 필드

사용자가 제안한 `STN_ID`, `DATE`, `TIME`, `SUM_RN`은 정규화 후 사용할 수 있는 이름이며 공식 API의 원본 필드는 다르다.

| 원본 필드 | 공식 의미 | 정규화 후보 |
| --- | --- | --- |
| `STN` | 국내 지점번호 | `station_id` |
| `TM` | 관측시각, KST | `observed_at` |
| `RN` | 강수량(mm) | `rainfall_mm` |
| `RN_DAY` | 해당 관측시간까지의 일강수량(mm) | 검증용 일 누적값 |
| `RN_INT` | 강수강도(mm/h) | `rain_intensity_mm_h` |
| `IR` | 강수 포함·무강수·결측 관련 코드 | 품질 및 결측 판별 |

API허브의 ASOS 기간 조회는 한 번에 최대 31일이다. 장기간 학습자료는 연 단위 CSV 파일셋을 받는 편이 호출 횟수와 재현성 면에서 더 적합하다. AWS는 더 촘촘한 지점망을 제공하지만 지점별 보유기간과 품질을 별도로 확인해야 한다.

### 행 수 해석

한 관측소의 완전한 10년 시간자료는 이론적으로 `365 × 24 × 10 ≈ 87,600`행이다. 윤년, 결측, 관측소 이력에 따라 실제 값은 달라진다. 이 수는 강수 원본 행 수일 뿐이며 최종 학습 표의 독립 표본 수는 아니다.

### 수집 판단

강수 원본 수집과 `rain_1h`, `rain_6h`, `rain_24h`, `max_rain` 생성은 가능하다. 다만 포항 ASOS 한 지점만 사용하면 같은 사건·시각의 모든 건물이 동일한 강수 특징을 갖는다. 건물별 국지 강우 차이를 만들려면 AWS 등 여러 지점의 좌표와 건물 위치를 결합해야 한다.

## 5. 건축물 데이터 — 건물 Feature 및 공간 단위

건축물 속성과 공간 도형은 분리해서 확인해야 한다.

### A. 건축물대장 표제부

| 항목 | 확인 내용 |
| --- | --- |
| 제공처 | [공공데이터포털 건축물대장 표제부](https://www.data.go.kr/data/15044720/fileData.do), [건축물대장 OpenAPI 묶음](https://www.data.go.kr/dataset/15004825/openapi.do?lang=ko) |
| 형식 | 전체 파일 XLSX, 활용 신청형 REST API |
| 주요 확인 속성 | 관리건축물대장PK, 주소·법정동 코드, 건물명, 주용도, 지상층수, 지하층수, 주차 관련 수·면적 |
| 좌표/도형 | 표제부 설명에는 위도·경도 또는 건물 Polygon이 없음 |
| 행 수 | `TBD` — 포항 필터 및 중복 정리 후 산정 |

사용자가 제안한 `LAT`, `LON`은 건축물대장 표제부에서 직접 확인되지 않는다. 주소/법정동/지번을 공간 건물 데이터와 연결해야 한다.

또한 `지하층수 > 0`은 지하 공간의 존재를 뜻할 뿐, 지하주차장을 직접 보장하지 않는다. 주차 관련 속성이나 층별 용도를 함께 확인해야 대상 건물을 더 정확히 좁힐 수 있다.

### B. GIS건물통합정보

| 항목 | 확인 내용 |
| --- | --- |
| 제공처 | [VWorld GIS건물통합정보](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=NA&dsId=18) |
| 형식 | 건물 Polygon을 포함한 SHP |
| 좌표계 | 최근 배포본 `EPSG:5186`, 과거 배포본 `EPSG:5174`로 페이지에 표기 |
| 갱신 | 월간·일간 변동 데이터 |
| 접근 | VWorld 로그인 필요, 대용량 다운로드 솔루션 안내 |
| 행 수 | `TBD` — VWorld의 전국 규모 표시는 참고만 하고 포항 파일 확보 후 산정 |

VWorld 페이지는 SHP 속성이 `A0 ... An`으로 표시되며 별도 컬럼 정의서를 참고하라고 안내한다. 정확한 건물 ID와 건축물대장 연결 키는 해당 정의서와 실제 포항 파일을 받은 뒤 확정할 수 있다.

### 수집 판단

건물 Polygon과 지하층·용도 속성을 각각 확보할 경로는 존재한다. 그러나 두 자료의 연결 키와 매칭률을 확인하기 전에는 `BULD_ID`, 좌표, 지하층 수가 한 행에 바로 온다고 가정할 수 없다.

### 수집 판단

실제 DEM 래스터를 확보하면 건물 위치의 고도와 주변 대비 고도차를 추출할 수 있다. 현재는 실제 파일의 포맷, 해상도, CRS와 다운로드 절차를 완료하지 않았으므로 데이터 수집 가능성을 확정하지 않는다.

## 8. 전체 수집 판단

현재 공식 제공 경로만 놓고 보면 다음 조합은 기술적으로 구성 가능하다.

```text
침수흔적 Polygon
+ 기상청 시간 강수
+ 건물 Polygon 및 건축물대장 속성
+ DEM 래스터
+ 하천 중심선
```

그러나 아직 “학습 가능한 데이터셋이 확보됐다”고 말할 수는 없다. 전체 데이터 확보 후 다음 수치가 나와야 한다.

- 포항의 실제 건물 수와 지하주차장 후보 수
- 침수 Polygon과 겹치는 양성 건물 수
- 서로 다른 침수 사건 수
- 정확한 시작 시각이 있는 사건 비율
- 데이터셋 간 건물 매칭률
- 컬럼별 결측률과 공간·시간 커버리지
