# 침수 위험 회피 대피 경로 설계

> 확인일: 2026-08-22
>
> 상태: `MVP IMPLEMENTED` — 포항 POSTECH 인근 OSM 도로망과 현재 로컬 위험·주차장 데이터로 재현 가능한 데모를 구현했다. 실제 안전 경로를 보증하지 않는다.

## 0. 구현 결과

- 생성기: `scripts/build_flood_aware_route.py`
- 실행: `./.venv/bin/python scripts/build_flood_aware_route.py`
- 기준 출발점: 위도 `36.014`, 경도 `129.325`
- OSM 운전 도로 범위: 출발점 반경 `2,500m`
- 위험 영향 반경: 건물 위험점 기준 `120m` (`DEMO` 파라미터)
- 목적지 후보: 가까운 공영주차장 최대 25곳 중 위험 영향권 밖이며 도로로 도달 가능한 후보
- 결과: `효곡동 노상1`, 도로거리 `618.3m`
- 현재 결과의 일반 최단경로와 저위험 경로: 동일. 두 경로 모두 생성된 위험 영향권 교차 길이 `0m`
- 출력: `outputs/routing/pohang-postech-flood-aware-route.geojson`, manifest, 프론트용 GeoJSON

경로가 동일한 것은 실패가 아니다. 현재 출발점과 선택 목적지 사이의 최단 도로가 데모 위험 영향권을 지나지 않았기 때문이다. 차이가 없는데도 임의 우회선을 만들지 않는다. 공식 현재 침수 폴리곤을 `--current-flood-geojson`으로 넣으면 교차 간선을 제거하고, 위험점을 지나야 하는 다른 위치·목적지에서는 패널티가 실제 경로 선택에 반영된다.

## 1. 결론

산불 사례의 `예측 셀 → 도로 제외·가중 → 대피소 선택 → 최단 경로` 구조를 Waterpark에 적용할 수 있다. 다만 현재 Waterpark 출력은 64×64 격자가 아니라 **지하층 보유 건물 25,336동의 점 단위 상시 위험도**다. 또한 정답은 지하주차장 침수가 아닌 지표면 침수이고, 현재 침수 도로 통제 정보도 없다.

따라서 1차 결과의 사용자 표현은 `안전 경로`가 아니라 다음처럼 제한한다.

- 침수 위험 구역을 피하도록 계산한 `저위험 우회 경로`
- 공공데이터와 지형 위험을 기준으로 한 `대피 경로 후보`
- 실제 재난문자·도로 통제와 현장 안내를 함께 확인해야 하는 경로

## 2. 산불 사례와 Waterpark의 대응 관계

| 산불 사례 | Waterpark 대응 | 현재 상태 |
| --- | --- | --- |
| 64×64 예측 셀 | 건물 위험 점 또는 추후 생성할 침수 위험 격자 | 건물 점만 있음 |
| 현재 산불 빨간 셀 | 현재 침수·도로 통제 구역 | 미확보 |
| 익일 산불 노란 셀 | 강수 조건을 반영한 가까운 미래 침수 위험 구역 | 모델 일반화가 낮아 규칙 기반 위험도만 있음 |
| 대피소 126곳 | 경북 공영주차장 후보 2,010곳 | 좌표 1,986곳, 안전성·실시간 여석 미검증 |
| OSM 도로 그래프 | 경북 시군별 운전 도로 `MultiDiGraph` | 포항 데모 구역 수집·GraphML 캐시 구현 |
| Dijkstra 최단 경로 | 거리·시간·침수 위험을 합친 비음수 비용 최소 경로 | 포항 데모 구현 |

## 3. 권장 처리 흐름

```text
사용자 현재 위치
  + 시군별 캐시된 OSM 운전 도로 그래프
  + 현재 침수·통제 폴리곤(확보 시)
  + 가까운 미래 침수 위험 폴리곤/격자
  + 안전 조건을 통과한 주차장 후보
→ 도로 간선과 위험 구역 공간 교차
→ 현재 침수 간선 제거
→ 예측 위험 간선에 비음수 패널티 부여
→ 후보 주차장별 위험 가중 최단 경로 계산
→ 목적지·경로·판정 근거를 GeoJSON으로 반환
```

### 3.1 도로 그래프

OSMnx의 `graph_from_polygon(..., network_type="drive")`로 시군 경계 안의 운전 도로를 `MultiDiGraph`로 만든다. 경상북도 전체를 서버 시작 때마다 Overpass API에서 받지 않고, 시군별 GraphML을 미리 생성해 `save_graphml`로 저장한 뒤 서버에서 `load_graphml`로 읽는 방식을 권장한다.

OSMnx 공식 문서는 큰 영역 요청이 여러 요청으로 분할될 수 있고 주의가 필요하다고 명시한다. 해커톤 데모에서도 네트워크 다운로드를 요청 시점에 수행하지 않는다.

### 3.2 위험 공간 만들기

현재 `gyeongbuk_underground_parking_risk.csv`는 건물 중심점과 위험 등급만 가진다. 이 점을 그대로 도로와 겹치면 도로 위험 범위를 표현할 수 없다. 다음 중 하나가 선행돼야 한다.

1. `DEMO`: 위험 점을 설정 가능한 영향 반경 또는 일정 격자로 변환한다. 반경·격자 크기는 안전 기준이 아니라 시연용 파라미터임을 표시한다.
2. `TARGET`: 레이더·강수·DEM·위험지도 등을 동일 격자에 결합해 각 셀의 위험도를 산출한다.
3. `OPERATIONS`: 실제 침수·도로 통제 폴리곤이 확보되면 현재 위험 레이어로 별도 사용한다.

모든 공간 연산은 위경도 좌표에서 직접 미터를 계산하지 않고, 경북 계산용 투영좌표계로 변환한 뒤 수행한다. GeoPandas `sjoin(..., predicate="intersects")`로 도로 간선과 위험 폴리곤의 교차 여부를 붙일 수 있다.

### 3.3 도로 비용

제안 비용은 모두 비음수로 유지한다.

```text
route_cost = travel_time 또는 length
           + predicted_flood_penalty
           + unknown_data_penalty
```

- `현재 침수 또는 공식 도로 통제`: 그래프에서 간선을 제거한다.
- `가까운 미래 고위험`: 간선은 남기되 큰 패널티를 부여한다.
- `자료 미상`: 안전으로 간주하지 않고 작은 불확실성 패널티 또는 경고를 붙인다.

NetworkX는 문자열 속성 또는 함수를 `weight`로 받아 Dijkstra 기반 최단 경로를 계산할 수 있다. 패널티의 실제 배수는 검증 전 확정하지 않는다.

### 3.4 목적지 필터

현재 경북 공영주차장 2,010곳은 대피 목적지 후보일 뿐 안전 주차장이 아니다. 목적지 후보는 최소 다음 조건을 통과해야 한다.

- 현재 침수·통제 구역 밖
- 가까운 미래 고위험 구역 밖
- 지하주차장이 아닌 지상·옥외 여부 확인
- 과거 침수 중첩, 상대고도와 접근 도로 위험 확인
- 운영 중 여부와 재난 대피 활용 가능 여부 확인
- 실시간 여석은 별도 데이터가 있을 때만 표시

`가까운 주차장`을 먼저 고른 뒤 경로를 검사하면 실패를 반복할 수 있다. 현재 위치에서 모든 유효 후보 또는 가까운 상위 후보군까지의 위험 가중 비용을 계산해 목적지와 경로를 함께 선택한다.

## 4. 좌표·셀 매핑

추후 CNN 또는 래스터 모델이 `행×열` 출력을 반환한다면 포항 사례처럼 셀 모서리 네 점을 서버에서 계산해 GeoJSON Polygon으로 반환할 수 있다. 필요한 메타데이터는 다음과 같다.

- 원점 또는 전체 bbox
- 셀 크기
- 행·열 방향, 특히 화면 배열과 북쪽 방향의 Y축 반전 여부
- 입력과 출력 CRS
- 모델 버전과 기준 시각

임의로 `64km×64km`를 경북 위에 늘려 붙이지 않는다. 모델 학습 입력을 만들 때 사용한 동일한 affine transform으로 역변환해야 한다.

## 5. 프론트 전달 형태 제안

구체 API 스키마는 백엔드 단계에서 확정한다. 최소 전달 객체는 다음 세 GeoJSON 계열이다.

- 위험 구역 `Polygon` 또는 `MultiPolygon`
- 선택 경로 `LineString`
- 목적 주차장과 현재 위치 `Point`

각 객체에는 `as_of_time`, 위험 근거, 모델/규칙 버전과 `verified` 상태를 함께 전달한다. 프론트는 위험 구역, 우회 경로와 목적지를 각각 다른 레이어로 그린다.

## 6. 해커톤 최소 구현 순서

1. `DONE` 포항 데모 구역 OSM 운전 도로를 GraphML로 캐시한다.
2. `DONE` 현재 건물 위험 점을 설정 가능한 영향권으로 변환한다.
3. `PARTIAL` 주차장 유형과 위험 영향권을 필터링한다. 실제 안전성·운영·여석 확인은 남아 있다.
4. `DONE` 도로 간선과 위험 공간을 교차해 위험 노출 길이와 비음수 비용을 만든다.
5. `DONE` 일반 최단 경로와 위험 가중 경로를 동시에 계산한다.
6. `DONE` GeoJSON을 생성하고 Kakao 지도 및 키 없는 SVG 폴백에 표시한다.
7. `OPEN` 경북 전역은 시군별 그래프 캐시, 경계 연결과 운영용 현재 통제 입력을 추가한다.

## 7. 검증 항목

- 반환 경로가 제거된 간선을 한 번도 통과하지 않는가
- 목적지가 현재·예측 위험 구역 밖인가
- 일방통행과 운전 가능 도로 방향을 지키는가
- 출발지 또는 목적지가 그래프와 단절됐을 때 실패 상태를 반환하는가
- 위험 회피로 인해 지나치게 긴 우회가 생길 때 사용자에게 거리·시간 차이를 알리는가
- 동일 입력과 동일 데이터 버전에서 결과가 재현되는가
- OSM 누락 도로와 재난 상황 중 새 통제를 안전하다고 오인하지 않는가

## 8. 기술·운영 한계

- 현재 저장소에는 백엔드가 없다. `osmnx`, `networkx`, `geopandas` 기반 오프라인 생성기와 프론트 정적 GeoJSON 연결만 구현했다.
- OSM 도로망은 실제 재난 시점의 침수·공사·통제를 자동 반영하지 않는다.
- 공개 Overpass API는 운영 백엔드가 아니므로 요청 시마다 의존하지 않는다.
- OSM 데이터 사용 시 ODbL과 OpenStreetMap 표시 의무를 적용한다.
- 현재 모델의 정답은 지표면 침수이며 새로운 호우에 대한 PR-AUC가 낮다. 이 결과만으로 사람의 안전을 보증하는 자동 대피 경로를 만들지 않는다.
