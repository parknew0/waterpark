# 경북 건물·강수·침수 데이터 소스 확인서

> 확인일: 2026-08-22
>
> 목적: 경상북도 건물별 위치와 지하주차장 여부를 만들고, 같은 위치·시각의 강수와 과거 침수 여부를 연결할 수 있는지 공식 제공처에서 확인한다.
>
> 상태: 제공 형식과 주요 컬럼을 확인했다. 경북 전체 원본과 API 인증키는 아직 확보하지 않았다.

## 1. 먼저 결론

원하는 정보가 한 파일에 모여 있지는 않다. 최소 다음 네 묶음을 결합해야 한다.

| 묶음 | 공식 데이터 | 얻는 정보 | 결합 기준 |
| --- | --- | --- | --- |
| 건물 위치 | VWorld GIS건물통합정보 | 건물 도형, 주소·지번, 건물명, 용도, 지상·지하층 수 | 건물 ID 후보, 법정동·지번, 위치 |
| 지하주차장 판별 | 건축HUB 건축물대장 표제부·층별개요 | 지하층 수, 옥내·옥외 주차 대수, 지하층의 용도 | 관리건축물대장 PK 또는 주소·지번 |
| 과거 강수 | 기상청 ASOS/AWS 시간자료와 지점정보 | 관측소 위치, 관측시각, 1시간 강수량 | 건물과 가까운 관측소 + 같은 시각 |
| 과거 침수 | 행정안전부 침수흔적도 | 침수 구역 또는 X·Y, 시작·종료시각, 침수심 | 건물 위치 + 사건 시각 |

따라서 최종 표는 공공데이터를 그대로 다운로드한 파일이 아니라, Waterpark가 직접 만드는 파생 데이터다.

```text
건물 위치·속성
+ 가까운 기상관측소의 시간별 강수
+ 같은 사건의 침수 공간 기록
= 건물 × 호우 사건 × 기준시각 표
```

## 2. 경북의 모든 건물 위치

### 공식 소스

- [VWorld GIS건물통합정보](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=NA&dsId=18)
- 제공 형식: Shapefile
- 검색 조건: `경상북도` + `전체데이터` + `SHP`
- 2026-08-22 확인 결과: 최신 목록의 기준일은 2026-08-09, 갱신일은 2026-08-19, 표시 용량은 약 290MB였다.
- 페이지 안내: 전체데이터는 월간, 변동데이터는 일간 제공이다.
- 좌표계: 기준일 2023-08-08 이후 배포본은 `EPSG:5186`, 2023-08-05 이전은 `EPSG:5174`로 안내된다.

사용자가 앞서 확인한 `CH_D010_00_20260820`은 `CH`, 즉 **변동데이터**다. 그날 추가·수정·삭제된 변화분이므로 경북 전체 건물 목록으로 사용하면 안 된다. 최초 기준표에는 `AL`, 즉 **전체데이터**를 받아야 한다.

### 확인된 주요 속성

VWorld가 제공하는 공식 컬럼 정의서에서 `AL_D010`의 다음 항목을 확인했다.

| 원본 필드 | 의미 | 사용 후보 |
| --- | --- | --- |
| `A1` | GIS건물통합식별번호 | 공간 건물 ID 후보 |
| `A2` | 고유번호(PNU) | 건축물대장 주소·지번 연결 후보 |
| `A3`, `A4`, `A5` | 법정동코드·명·지번 | 건축물대장 연결·검증 |
| `A8`, `A9` | 건축물 용도코드·명 | 건물 용도 |
| `A19` | 건축물 ID | 연결 키 후보 |
| `A24`, `A25` | 건물명·동명 | 중복 건물 구분 보조 |
| `A26`, `A27` | 지상층 수·지하층 수 | 건물 특징, 대상 후보 필터 |
| SHP geometry | 건물 Polygon | 대표점 생성과 공간 결합 |

Shapefile의 좌표를 WGS84(`EPSG:4326`)로 변환하고 건물 안쪽의 대표점 하나를 만들면 `latitude`, `longitude`를 얻을 수 있다. 모델 입력에 건물 모양 전체가 반드시 필요한 것은 아니다. 다만 원본 Polygon은 대표점 생성과 침수 구역 중첩 검증을 위해 보존하는 편이 좋다.

## 3. 지하주차장 여부

### 공식 소스

- [국토교통부 건축HUB 건축물대장정보 OpenAPI](https://www.data.go.kr/data/15134735/openapi.do)
- [건축물대장 표제부 파일 안내](https://www.data.go.kr/data/15044720/fileData.do)
- [건축HUB 건축물대장 층별개요](https://www.hub.go.kr/portal/opn/tyb/idx-bdrg-flr.do)

OpenAPI는 기본개요·표제부·층별개요 등을 JSON/XML로 제공한다. 표제부에는 관리건축물대장 PK, 법정동·지번, 건물명, 주용도, 지상·지하층 수와 다음 주차 관련 값이 있다.

- 옥내 기계식 주차 대수·면적
- 옥외 기계식 주차 대수·면적
- 옥내 자주식 주차 대수·면적
- 옥외 자주식 주차 대수·면적

그러나 `옥내 주차`는 `지하주차`와 같은 말이 아니다. 지상 주차동도 옥내일 수 있다. 따라서 표제부만으로 지하주차장 여부를 확정하면 오분류가 생길 수 있다.

층별개요에는 `층구분코드`가 있으며 공식 안내상 `10`은 지하, `20`은 지상이다. 지하층 행의 주용도명 또는 기타용도에서 주차장 용도를 확인할 수 있다면 더 직접적인 근거가 된다.

초기 판별값은 단순한 참·거짓보다 다음처럼 근거 강도를 함께 남기는 것이 안전하다.

| 판별값 | 조건 후보 | 뜻 |
| --- | --- | --- |
| `confirmed` | 지하층 행에서 주차장 용도를 확인 | 지하주차장 근거가 직접 있음 |
| `probable` | 지하층 수가 1 이상이고 옥내 주차 대수가 1 이상이나 층 용도 미확인 | 가능성이 높지만 확정할 수 없음 |
| `unknown` | 연결 실패, 층별용도 누락 또는 근거 부족 | 없다고 판단한 것이 아님 |

[한국교통안전공단 건축물대장 주차정보](https://www.data.go.kr/data/15135777/fileData.do)는 다운로드가 쉬운 보조 CSV다. 다만 2022년 말 기준의 1회성 자료이고, 주소코드·본번·부번 단위이며 좌표와 건물 PK가 없다. 옥내 주차가 지하주차를 뜻하지도 않으므로 주 데이터보다 교차검증용에 가깝다.

## 4. 건물 위치의 몇 년 몇 월 며칠 몇 시 강수량

### 공식 소스

- [기상자료개방포털 ASOS 시간자료](https://data.kma.go.kr/data/grnd/selectAsosRltmList.do?pgmNo=36&tabNo=2)
- [기상청 API허브 AWS](https://apihub.kma.go.kr/apiList.do?seqApi=2&seqApiSub=239)
- [기상자료개방포털 관측지점정보](https://data.kma.go.kr/tmeta/stn/selectStnList.do?pgmNo=123)

여기서 가장 중요한 점은 기상청이 **모든 건물 좌표에서 비를 측정하는 것이 아니라 관측소에서 측정한다**는 것이다. 그러므로 “건물 좌표의 강수량”은 우선 다음 방식으로 만든다.

1. 관측지점정보에서 각 ASOS/AWS의 지점번호, WGS84 위도·경도, 운영기간을 받는다.
2. 각 건물과 가장 가까우면서 해당 시각에 운영 중인 관측소를 찾는다.
3. 그 관측소의 같은 시각 강수량을 건물에 붙인다.
4. `station_distance_km`를 남겨 관측소가 너무 먼 행을 구분한다.

### 확인된 시간자료 값

| 자료 | 원본 필드 | 의미 |
| --- | --- | --- |
| ASOS | `TM`, `STN` | 관측시각(KST), 지점번호 |
| ASOS | `RN` | 강수량(mm) |
| ASOS | `RN_DAY`, `RN_INT` | 시각까지의 일강수량, 강수강도(mm/h) |
| AWS | `TM`, `STN` | 시각(KST), 지점번호 |
| AWS | `RN_HR1` | 과거 1시간 강수량(mm) |
| AWS | `RN_DAY` | 해당 시각까지의 일강수량(mm) |

`rain_6h`, `rain_24h`는 같은 관측소의 시간별 강수량을 각각 과거 6시간과 24시간 동안 합산해 만든다. 관측소 하나의 값을 경북 모든 건물에 붙이지 말고, 경북 및 도 경계 인근의 여러 AWS/ASOS를 함께 비교해야 한다.

이 방식은 가장 가까운 관측소의 실측값이지 건물 바로 위의 완전한 실측값은 아니다. 건물별 정밀 강우가 필요하다고 확인된 경우에만 레이더 격자 강수나 관측소 보간을 별도 후보로 검토한다.

## 5. 그때 그 건물 주변에 침수가 있었는지

### 기존 침수흔적도: Polygon과 시각이 있음

- [행정안전부 침수흔적도](https://www.safetydata.go.kr/disaster-data/view?dataSn=108)
- API: `GET /V2/api/DSSP-IF-00117`
- 전체 데이터: 회원가입 후 활용신청과 `serviceKey` 필요
- 공개 미리보기·샘플: 최대 100건

공개 미리보기에서 다음을 직접 확인했다.

| 필드 | 의미 |
| --- | --- |
| `FLDN_BGNG_YMD`, `FLDN_BGNG_TM` | 침수 시작일자·시각 |
| `FLDN_END_YMD`, `FLDN_END_TM` | 침수 종료일자·시각 |
| `FLDN_DOWA`, `FLDN_AREA` | 침수수심·면적 |
| `STDG_CTPV_CD`, `STDG_SGG_CD` | 시도·시군구 코드 |
| `GEOM` | WKT `POLYGON(...)` 침수 구역 |

경북 코드 `47`로 필터링한 뒤 건물 대표점이 `GEOM` 안에 들어가고 해당 사건의 시간 구간과 일치하면, 그 건물·사건을 `surface_flood_observed=1`인 양성 후보로 만들 수 있다. 건물 Polygon과 침수 Polygon의 겹친 비율도 보조값으로 계산할 수 있다.

### 새 심선·위선: Polygon이 없음

- [침수흔적도_심선](https://www.safetydata.go.kr/disaster-data/view?dataSn=3845)
- [침수흔적도_위선](https://www.safetydata.go.kr/disaster-data/view?dataSn=3846)

2025년에 등록된 심선·위선 자료에는 `GEOM` Polygon이 없다. 플랫폼의 공식 문의 답변도 심선·위선은 Polygon을 제공하지 않는다고 명시한다. 공개 미리보기에서 X·Y와 행정구역 코드를 확인했고, 위선에는 시작·종료일자와 시분, 평균침수위가 있다. 위선 좌표계는 플랫폼 답변상 `EPSG:3857`이다.

따라서 새 위선 자료만으로 “건물 안이 침수됐다”를 판정할 수는 없다. 기존 Polygon 자료의 기간·경북 커버리지가 충분한지 먼저 확인해야 한다. 새 위선은 사건 시각과 침수위 보강 또는 위치 근접 검토에 사용할 수 있지만, 거리 기준만으로 라벨을 만들면 그 기준 자체가 가정이 된다.

### 라벨의 의미와 한계

- 침수흔적도와 겹치면 **그 위치의 지표면 침수 기록**은 확인할 수 있다.
- 이것이 해당 건물의 **지하주차장이 실제로 침수됐다는 직접 기록**은 아니다.
- 침수흔적도 밖이라는 이유만으로 `0`을 주면 안 된다. 조사되지 않았거나 기록이 누락됐을 수 있다.
- 현재 확인한 공식 소스에는 경북 모든 지하주차장의 침수 여부가 참·거짓으로 정리된 단일 데이터가 없었다.

그러므로 현재 가능한 정답 이름은 `underground_parking_flooded`보다 `surface_flood_observed`가 정확하다. 실제 음성(`0`)을 어떻게 만들지는 전체 자료의 조사 범위와 사건 수를 확인한 뒤 정해야 한다.

## 6. 실제로 만들 중간 테이블

### 6.1 `buildings`

```text
building_id, pnu, building_name, address,
latitude, longitude, main_purpose,
underground_floor_count, indoor_parking_count,
underground_parking_status, underground_parking_evidence
```

한 행은 건물 하나다. VWorld 전체데이터를 기준으로 건축HUB 표제부·층별개요를 연결한다.

### 6.2 `weather_stations`와 `rain_hourly`

```text
station_id, station_name, latitude, longitude,
active_from, active_to
```

```text
station_id, observed_at_kst, rain_1h_mm, quality_flag
```

### 6.3 `flood_events`

```text
event_id, event_start_kst, event_end_kst,
flood_depth, flood_geometry, source_record_id, source_version
```

기존 Polygon 자료와 새 위선 자료는 공간 표현이 다르므로 `source_version`을 반드시 분리한다.

### 6.4 `building_event`

```text
building_id, event_id, as_of_time,
station_id, station_distance_km,
rain_1h, rain_6h, rain_24h,
surface_flood_observed, label_quality
```

한 건물은 여러 호우 사건과 여러 기준시각에 반복해서 등장한다. 이 표가 XGBoost에 넣을 문제지 후보이고, `surface_flood_observed`가 현재 만들 수 있는 정답 후보다.

## 7. 직접 확인할 순서

1. VWorld에서 `GIS건물통합정보 → 경상북도 → 전체데이터 → SHP`를 선택한다. `CH` 변동데이터를 전체 목록으로 사용하지 않는다.
2. 공공데이터포털에서 `건축HUB 건축물대장정보 서비스` 활용신청을 하고 표제부와 층별개요의 경북 표본을 조회한다.
3. 한 건물을 골라 VWorld의 PNU·지번·건물명과 건축물대장 관리 PK가 어떻게 연결되는지 확인한다.
4. 기상자료개방포털에서 경북 및 인접 지역 AWS/ASOS 지점정보와 시간 강수 CSV를 내려받는다.
5. 재난안전데이터 공유플랫폼에서 기존 `행정안전부_침수흔적도` 샘플을 확인하고 전체 API 활용신청을 한다.
6. 경북 전체 파일을 받은 뒤에만 건물 매칭률, 지하주차장 확인률, 침수 양성 건물 수와 사건 수를 계산한다.

## 8. 아직 확인되지 않은 것

- VWorld 건물과 건축HUB 대장을 한 번에 연결하는 공통 키의 실제 매칭률
- 경북 전체 건물 수와 지하주차장 `confirmed` 건물 수
- 기존 침수 Polygon의 경북 수록 기간·사건 수와 최신성
