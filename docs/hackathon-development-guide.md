# Waterpark 해커톤 개발 가이드

> 목적: 구현 세부사항을 정하는 문서가 아니라, 이 대회의 요구와 심사 기준에 맞춰 Waterpark를 개발하기 위한 상위 원칙을 공유한다.
>
> 기준: 2026-08-22에 제공된 JunctionX Korea 2026 Hacker Dashboard와 행사 메모

## 1. 프로젝트와 트랙의 연결

Waterpark는 공공데이터와 머신러닝을 이용해 경상북도 지하주차장의 침수 위험을 예측하고 차량 사전 대피를 안내한다. 트랙이 제시한 두 방향 중 **공공데이터를 활용한 지역 문제 해결 서비스**에 해당한다.

트랙이 원하는 흐름은 다음과 같다.

```text
경상북도의 지하주차장 침수 문제
→ 관련 공공데이터 판별 및 가공
→ 머신러닝을 통한 침수 위험 예측
→ 실제 서비스에서 사용할 수 있는 결과 제공
```

다음과 같은 결과물은 피한다.

- 실제 공공데이터가 연결되지 않은 UI 목업
- 원본 데이터를 가공 없이 보여주는 데이터 뷰어
- 결과가 만들어지는 과정을 설명할 수 없는 데모
- 실행 방법과 한계가 드러나지 않는 일회성 구현

## 2. 심사 기준에 따른 개발 원칙

Hacker Dashboard에 표시된 최신 배점을 기준으로 한다. 행사 전사본에는 다른 배점이 기록되어 있으므로 최종 제출 시 공식 화면을 기준으로 한다.

### Technical Completeness — 25%

- 최소 한 개 이상의 실제 공공데이터가 예측 결과에 영향을 줘야 한다.
- 데이터의 수집, 전처리, 머신러닝, 백엔드와 프론트엔드 전달 과정이 이어져야 한다.
- 각 기술 선택이 데이터와 제한 시간에 맞는 이유를 설명할 수 있어야 한다.
- 핵심 흐름은 처음부터 끝까지 재현 가능해야 한다.
- 데이터와 모델의 한계를 숨기지 않는다.

개발 원칙: 기능 수보다 실제 데이터가 끝까지 흐르는 작은 범위의 완성도를 우선한다.

### Potential for Public-Sector Use — 25%

- 경상북도 공공데이터가 프로젝트의 핵심 재료여야 한다.
- 결과가 지하주차장 침수 대응에 어떻게 사용되는지 명확해야 한다.
- 위험 예측의 근거와 한계를 공공기관이 이해할 수 있어야 한다.
- 특정 지역에서 시작하더라도 경상북도 내 다른 지역으로 확장할 수 있는 구조를 고려한다.

개발 원칙: 공공기관이 결과를 신뢰하고 활용하려면 무엇을 확인할 수 있어야 하는지 보여준다.

### Innovation & Differentiation — 20%

Waterpark의 차별화 방향은 단순한 날씨 또는 재난 알림이 아니라 **침수 위험을 미리 예측하고 행동으로 연결하는 것**이다.

- 광역 날씨가 아닌 지하주차장과 주변 환경의 맥락을 반영한다.
- 위험 수치만 보여주지 않고 차량 사전 대피 판단에 연결한다.
- 여러 공공데이터를 예측에 사용할 수 있는 형태로 가공한다.

개발 원칙: AI를 사용했다는 사실보다 기존 알림과 비교해 어떤 정보와 행동이 달라지는지를 보여준다.

### Sustainability & Impact — 20%

- 사용하는 데이터가 지속적으로 제공되고 갱신 가능한지 확인한다.
- 데이터의 라이선스, 호출 제한과 운영 비용을 기록한다.
- 데이터 수집과 전처리 과정이 다른 지역에도 적용 가능한 형태인지 고려한다.
- 해커톤 이후 데이터 또는 모델을 교체·개선할 수 있도록 구성한다.

개발 원칙: 프로토타입의 범위는 작게 유지하되, 데이터와 처리 과정은 이어서 개선할 수 있게 만든다.

### Prototype Bonus — 10%

- 실제 공공데이터가 예측 결과를 만드는 장면을 보여준다.
- 전처리부터 사용자에게 전달되는 결과까지 하나의 흐름으로 시연한다.
- 라이브 데이터에 문제가 생겨도 같은 흐름을 재현할 수 있어야 한다.

개발 원칙: 프로토타입은 화면의 양보다 Waterpark의 핵심 데이터 흐름을 증명해야 한다.

## 3. 현재 개발 순서

현재 합의된 범위는 다음 순서까지다.

1. 전처리에 사용할 데이터 판별 및 전처리
2. 전처리 결과를 사용하는 머신러닝
3. 머신러닝 결과를 제공하는 백엔드 구축
4. 백엔드 결과를 프론트엔드에 전달

각 단계의 세부 설계는 해당 단계에서 조사하고 결정하며, 결정되기 전 내용을 문서에서 미리 확정하지 않는다.

## 4. 발표와 문서에서 유지할 원칙

- 실제로 구현한 것과 계획만 있는 것을 구분한다.
- 공공데이터의 출처와 Waterpark에서의 역할을 설명한다.
- 데이터 전처리와 머신러닝 결과가 연결되는 과정을 보여준다.
- 기술적 한계와 아직 확인하지 못한 부분을 과장하지 않는다.
- 발표의 주장과 실제 데모가 일치해야 한다.
